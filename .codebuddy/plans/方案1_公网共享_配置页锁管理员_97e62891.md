## 用户需求

实施"公网共享 + 配置页锁管理员"方案（方案1）：

1. 后端 `/api/config/runtime`（GET/POST）仅允许管理员访问，普通登录用户返回 403，防止任意用户查看/覆盖全局共享的 API 配置。
2. 用户信息接口（`/auth/me` 以及登录、刷新返回的用户对象）增加 `is_admin` 字段，供前端判断身份。
3. 前端"服务配置"表单仅管理员可见，非管理员隐藏，普通用户只能看到"仅管理员可配置"的说明。
4. 补充 `.env.example` 的 `ADMIN_USERNAMES` 配置项，并在 README 中说明"共享 Key + 仅管理员可配置"的公网部署方式。

## 核心功能

- 管理员名单机制：通过环境变量 `ADMIN_USERNAMES`（逗号分隔的用户名）判断管理员，不新增数据库字段、不做迁移。
- 配置接口门禁：在路由层对 config 路由单独加管理员依赖，其余业务路由仍保持"登录即可访问"。
- 身份透出：`is_admin` 随用户信息返回，前端据此隐藏/展示配置表单。
- 前端兜底：普通用户访问配置接口被拒时，界面优雅降级隐藏表单，而不是报错。

## 技术栈选择

- 后端：Python 3 + FastAPI + Pydantic（复用现有 `Depends` 依赖注入与 `HTTPException` 模式）。
- 前端：Vue 3 + Element Plus + Pinia（复用现有 `userStore.userInfo` 登录态）。
- 配置：复用现有 `.env` / pydantic-settings 体系，不引入新依赖。

## 实施方案

以"最小改动、不加数据库字段"为原则，把管理员判定收敛到后端依赖层，前端只做展示层的显隐控制。

### 后端

1. `app/core/config.py`：在 `Settings` 中新增 `ADMIN_USERNAMES: str = ''`（逗号分隔管理员用户名）。
2. `app/api/deps.py`：新增 `require_admin` 依赖，复用 `get_current_user` 校验登录态，再判断 `current['username']` 是否在管理员名单中，否则抛 `HTTPException(403)`。
3. `app/api/router.py`：将第 26 行 `config_router` 的依赖由 `_protected`（仅登录）改为 `[Depends(require_admin)]`；第 20 行 `_protected` 保持不变，其余业务路由不受影响。
4. `app/schemas/auth.py`：`UserProfile` 增加 `is_admin: bool = False` 字段。
5. `app/api/routers/auth.py`：`_to_profile` 根据 `username ∈ ADMIN_USERNAMES` 计算 `is_admin`；`/me`、登录、刷新三处返回统一复用该函数，自动透出管理员身份。

### 前端

6. `frontend/src/views/Profile.vue`：从 `userStore.userInfo` 读取 `is_admin`，非管理员时用 `v-if` 隐藏配置表单，仅显示"服务配置仅管理员可改"提示；`loadConfig` 收到 403 时同样进入隐藏/提示状态（兜底处理 localStorage 中身份过期的情况）。

### 配置与文档

7. `.env.example`（不存在则新建）：增加 `ADMIN_USERNAMES=admin` 及注释说明。
8. `README.md`：补充公网部署说明——服务器手动创建 `.env` 填共享 Key，`docker compose` 经 `env_file` 注入；普通用户不接触配置，所有访问共用服务器 Key，并提示费用归属。

## 实施要点

- 管理员名单解析需处理空串、空白、重复项：`[n.strip() for n in settings.ADMIN_USERNAMES.split(',') if n.strip()]`。
- `require_admin` 要先 `Depends(get_current_user)`，保证未登录返回 401、已登录非管理员返回 403，语义清晰。
- `settings` 存在 `@lru_cache` 且 `runtime_config` 写回时会 `cache_clear()`，新增 `ADMIN_USERNAMES` 后行为与现有配置一致；管理员名单变更需重启生效（与 `.env` 配置一致）。
- 前端隐藏逻辑以 `userStore.userInfo.is_admin` 为主、403 兜底为辅，避免 localStorage 数据过期导致配置面板意外暴露。
- 不动数据库、不改 `runtime_config` 的读写逻辑、不改高德/LLM 调用链路，保持改动面最小。

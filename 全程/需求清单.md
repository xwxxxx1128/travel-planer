# 需求清单 —— 智能多景点旅行规划 Agent 系统

> 版本：v1.0 ｜ 状态：已评审基线 ｜ 关联文档：《PRD需求分析.md》《非功能性需求.txt》
>
> 本文是需求的**唯一来源清单**（Single Source of Truth）：先定业务目标、角色、约束、边界与风险，再展开逐条可追踪的功能需求（FR 编号供 PRD / 设计 / 测试引用）。

---

## 1. 业务目标

| 编号 | 目标 | 度量方式 |
| --- | --- | --- |
| G-1 | 用对话式 Agent 完成"规划 — 推荐 — 检索 — 预订"旅行闭环，替代多平台手工拼接 | 用户可在单一会话内完成行程生成、POI 推荐、评价查询、航班预订全流程 |
| G-2 | 抑制 LLM 幻觉，保证评价 / 攻略类回答可溯源 | 评价类问题走"数据库 → Tavily 联网 → 写库"确定性预检索，回答附来源 |
| G-3 | 敏感写操作可控 | 航班预订 / 取消 100% 经 HITL 二次确认后才写库 |
| G-4 | 多景点行程编排自动化 | 输入目的地与天数即产出分天行程，游览顺序经 TSP 优化，含交通耗时与时间窗 |
| G-5 | 低门槛部署与配置 | `docker compose up --build` 一键部署；模型 / 高德 / Tavily Key 可由管理员（`ADMIN_USERNAMES` 指定）在前端运行时配置，热生效 |

## 2. 角色

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 游客 | 未登录访问者 | 仅登录 / 注册页 |
| 注册用户 | 系统基础业务角色（无完整角色/后台体系，仅以 `ADMIN_USERNAMES` 区分管理员） | 对话、行程规划、地图路线、航班查询与预订、旅行清单；服务配置仅管理员可用 |
| 部署者 | 负责部署运维的人（不进系统，通过 `.env` / Docker 管理） | 环境变量、容器编排、数据库与向量库持久化目录 |

> 事实依据：`users` 表无角色字段，管理员由环境变量 `ADMIN_USERNAMES`（逗号分隔用户名）判定；`/api/config/runtime` 经 `require_admin` 依赖保护（未登录 401、非管理员 403），`is_admin` 随 `/api/auth/me` 返回。前端路由按登录态（`requiresAuth` + `authApi.me()` 校验）拦截，JWT access + refresh 双令牌。

## 3. 约束

| 编号 | 类型 | 约束内容 |
| --- | --- | --- |
| C-1 | 技术 | 后端 Python 3.11+ / FastAPI / SQLAlchemy；前端 Vue3 + Vite + Element Plus + Pinia；Agent 编排绑定 LangGraph |
| C-2 | 技术 | LLM 须为 OpenAI 兼容接口（默认 `deepseek-ai/DeepSeek-V3` via SiliconFlow，可换供应商） |
| C-3 | 技术 | 地图能力绑定高德开放平台（Web API + JS API），需自备 Key |
| C-4 | 技术 | 联网检索依赖 Tavily MCP（`tavily-mcp` 子进程），需自备 Key |
| C-5 | 数据 | 航班班次为本地 demo 库 `travel_new.sqlite`（与业务库解耦，可整体重置 / 日期平移）；预订单存业务库 `flight_bookings` 表 |
| C-6 | 运行 | 数据库默认 SQLite（可切 PostgreSQL）；向量库 Chroma（Docker 容器内 8000 端口，经 compose 内网访问） |
| C-7 | 部署 | Docker Compose：前端 3000 为统一入口（nginx 反代 `/api` 到 backend:8000）；后端 / Chroma / MCP 仅容器内网互通（`expose`），不映射宿主机端口；数据库与向量库持久化目录被 `.gitignore` 忽略 |

## 4. 业务边界

### 4.1 范围内（In Scope）
- 用户注册 / 登录 / JWT 鉴权（含 refresh 静默续期）；
- 对话式智能助理（SSE 流式、意图识别、工具调用、子 Agent 委托、HITL 中断确认、会话 Checkpointer 持久化与历史恢复）；
- 多景点行程规划与分天产出（由对话式 Agent 提供，行程可入库 itineraries 三级结构）；
- 高德 POI 搜索、地理编码、路线规划、TSP 多目的地顺序优化、地图可视化；
- 航班班次查询、对话内改签 / 取消（软取消，保留记录）、航班卡片"加入我的航班"、个人"我的航班"列表；
- 酒店 / 餐饮 / POI 推荐（高德实时 + 向量知识库）；
- 景点评价 / 攻略检索（本地 30 天缓存优先，未命中 Tavily 联网并回写，`poi_key` 归一化缓存）；
- 旅行清单（手动添加 / 对话中加入 / 推荐卡片加入，按用户隔离）；
- 运行时配置中心（仅管理员；模型 / 高德 / Tavily Key，保存后写 `.env` 并热更新 `os.environ`）；
- 健康检查、Swagger 文档、pytest 测试、Docker 一键部署。

### 4.2 范围外（Out of Scope）
- ❌ 真实航司 / OTA 交易对接，不产生任何真实资金操作（改签 / 取消为模拟闭环）；
- ❌ 完整多角色权限体系、组织 / 团队、多租户（仅保留基于 `ADMIN_USERNAMES` 的轻量管理员判定）；
- ❌ 移动端 App / 小程序（仅响应式 Web）；
- ❌ 多语言国际化；
- ❌ 按目的地自动爬取并同步向量库（接口 `/api/crawl` 已预留，属后续规划）；
- ❌ Agent 执行轨迹可观测性面板（后续规划）。

## 5. 风险

| 编号 | 风险 | 等级 | 影响 | 应对措施 |
| --- | --- | --- | --- | --- |
| R-1 | LLM 幻觉编造评价 / 攻略 | 高 | 信息不可信，损害产品核心价值 | 入口意图识别 + 确定性预检索（DB→Tavily→写库），材料注入上下文，无材料不臆造；`poi_key` 归一化让不同叫法命中同一缓存 |
| R-2 | 高德 / Tavily Key 缺失或失效 | 高 | 地图 / 联网检索功能不可用 | 支持管理员在前端运行时配置 Key 热生效；本地缓存兜底；Agent 友好提示 |
| R-3 | 敏感操作误触发（误订 / 误取消） | 高 | 数据错乱、用户信任受损 | LangGraph `interrupt_before` 挂起 + 前端确认框 + `/chat/resume` 才写库；软取消保留记录可追溯（`booking_no`） |
| R-4 | SSE 长连接被反向代理缓冲 | 中 | 前端长时间零字节超时 | 响应头 `X-Accel-Buffering: no` 关闭 nginx 缓冲；节点级事件推送保活 |
| R-5 | LLM 供应商限流 / 故障 | 中 | 核心对话不可用 | OpenAI 兼容协议可随时切换供应商（运行时配置）；Temperature 等参数可调 |
| R-6 | demo 航班库被业务写操作污染 | 中 | 演示数据不可复现 | 班次库与业务库物理分离（`travel_new.sqlite` vs SQLAlchemy 业务库）；预订单只写业务库 |
| R-7 | 会话中断后前端状态丢失 | 中 | 确认框丢失、流程断头 | `/chat/pending` 供前端重连后恢复中断态；`/chat/history/{session_id}` 恢复对话记录 |
| R-8 | 向量库与业务库数据漂移 | 低 | 推荐与库存不一致 | POI / 评论类知识经 Chroma 集合增量补充；评价缓存带 `expires_at` 过期重建 |
| R-9 | 越权访问他人数据 | 低 | 数据泄露 | 服务端按 JWT 解析 `user_id`，忽略前端传入的身份字段；清单 / 预订按 `user_id` 隔离 |

## 6. 功能需求清单

> 优先级：P0 必须 / P1 应该 / P2 可选。编号规则：FR-<模块字母><序号>，与《PRD需求分析.md》第 5 节一一对应。

## 7. 术语

| 术语 | 说明 |
| --- | --- |
| HITL | Human-in-the-Loop，敏感操作中断等待二次确认 |
| Checkpointer | LangGraph 会话状态持久化机制，按 `session_id` 恢复 |
| poi_key | 景点名归一化后的缓存键（`城市::规范景点名`），统一同义景点缓存 |
| CompleteOrEscalate | 子 Agent 主动交还主助理的信号 |
| TSP | 旅行商问题，多景点顺序优化 |
| 软取消 | 取消不删记录，仅置 `status=cancelled`，凭 `booking_no` 追溯 |
